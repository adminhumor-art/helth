# Сладкая

Рабочий монорепозиторий продукта для прямого получения показаний CGM,
локальных тревог и семейного удалённого наблюдения.

Текущая сборка — инженерный прототип. Полный цикл ещё не испытан на реальном
Samsung и физическом датчике и не имеет медицинской или клинической валидации.

## Состав

- `android/` — приложение пациента и драйверы датчиков;
- `backend/` — API, хранение, правила тревог и Telegram;
- `web/` — семейный сайт;
- `contracts/` — общий API-контракт;
- `docs/` — границы продукта, решения и протокол испытаний.

Канонические рабочие документы:

- [`docs/PRODUCT_CONCEPT.md`](docs/PRODUCT_CONCEPT.md) — общая концепция на согласование;
- [`docs/ROADMAP.md`](docs/ROADMAP.md) — последовательность рабочих итераций;
- [`docs/CODE_AUDIT.md`](docs/CODE_AUDIT.md) — что оставить, переделать и изолировать;
- [`docs/DECISIONS.md`](docs/DECISIONS.md) — решения владельца;
- [`docs/WORKLOG.md`](docs/WORKLOG.md) — журнал фактических проверок;
- [`docs/PROJECT_MEMORY.md`](docs/PROJECT_MEMORY.md) — краткая память проекта;
- [`docs/HOW_APP_WORKS.md`](docs/HOW_APP_WORKS.md) — как проходит показание и где нужен интернет;
- [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md) — установка и первый тест на телефоне.

В рабочую сборку входят только компоненты «Сладкой» и явно подключённые
библиотеки производителя датчика.

## Текущий этап

Программно собран полный локальный путь: код с упаковки → BLE-поиск → изолированная
диагностика → явная exact-активация выбранной свежей точки → нативное ядро и
checkpoint → Room → крупное значение, график, локальная тревога и виджет.
Активная локальная конфигурация восстанавливается при следующем запуске. Интернет
для этого пути не нужен.

GS1 и GS1Sb используют один пользовательский поток для международного и
китайского профилей. Этот код ещё нужно проверить с физическим датчиком, особенно
китайский вариант, выбор внутреннего протокола и калибровки. GS3 остаётся
отдельным направлением: текущая Android-сборка не имеет полного onboarding,
BLE/product driver и подтверждённого нативного пути для него.

Backend, семейный экран и Telegram-контур реализованы программно, а опубликованный
сайт пока показывает только синтетические данные. Сайт получает удалённую копию
показания и не может менять датчик, локальную историю, пороги, тревогу или
виджет. Для живого семейного режима ещё нужны отдельный deploy сервера,
защищённая браузерная сессия и реальные настройки Telegram.

Граница исходного кода прямых драйверов зафиксирована в
[`docs/LICENSING.md`](docs/LICENSING.md).
