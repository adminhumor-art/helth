# Аудит текущего кода

Статус: актуализировано после реализации программного контура ядра GS1/GS1Sb.

Обновлено: 1 августа 2026 года.

## Вывод

Переписывать весь проект заново не требуется. Полезная продуктовая основа уже
есть, но её дальнейшая разработка не является текущим приоритетом. Сначала нужно
доказать сенсорный тракт. Существование файла или зелёного теста не означает, что
поведение одобрено для реального датчика.

Аудит исследовательского upstream также не подтверждает ни полный fork, ни
свободное переписывание протокола. Полный проект содержит ценное полевое знание,
но его сенсоры, JNI, хранение, сеть, график и интерфейс собраны в сильно связанный
монолит. Рабочая граница: неизменяемый эталон, официальное нативное ядро и свой
узкий адаптер с replay-проверкой каждого результата и состояния.

## Сохранить как продуктовую основу после ядра

| Часть | Почему нужна | Что ещё проверить |
| --- | --- | --- |
| Android Compose: карточка значения и график | Уже соответствует главному порядку экрана | Свежесть, пропуски, навигация и доступность |
| `SensorDriver` | Отделяет источник данных от приложения | Расширить статусы и происхождение показания |
| Симулятор | Нужен для TDD тревог и потерь связи | Добавить сценарии пропусков, восстановления и перезапуска |
| Room и очередь отправки | Нужны для офлайн-работы | Атомарное ядро реализовано; проверить миграцию и откат транзакции на Android, затем связать с очередью продукта |
| Фоновая служба и уведомления | Нужны для локальной тревоги | Настройки, разрешения, повтор и проверка на Samsung |
| Backend-монолит, PostgreSQL и Telegram-очередь | Соответствуют текущему масштабу | Авторизация, настройки семьи и новая модель данных |
| Визуальная основа сайта | Крупное число и график уже на месте | Подключить настоящий API, свежесть и сохранение подтверждений |

## Обязательно переделать

| Часть | Фактическая проблема |
| --- | --- |
| Модель измерения Android/backend/API | Сейчас хранит одно число и не объясняет его происхождение или коррекцию |
| График Android | Соединяет все соседние элементы списка, даже если между ними большой пропуск |
| Статус Android «На связи» | Может основываться на наличии старого значения, а не на реальной свежести |
| Пороговые линии графика | Сейчас целевой диапазон и пороги тревог заданы независимо и расходятся |
| Настройки тревог | Интерфейса и постоянного хранилища нет; значения зашиты в код |
| Сайт | Сейчас это статическая демонстрация, не подключённая к backend |
| Контракт тревоги | Не хранит версию настроек и происхождение числа, вызвавшего тревогу |
| Состояние тревог | Android держит его в памяти; backend после рестарта восстанавливает не все открытые тревоги |
| Сквозной поток | Обычный Android-запуск fail-closed, реальный драйвер ещё не подключён к UI; отправка на backend не настроена, сайт API не вызывает |
| Виджет | Может продолжать показывать старое число без заметного статуса устаревания |

## Диагностический карантин

Сенсорный модуль не подключён к экрану: обычный запуск показывает отсутствие
подтверждённого источника, а симулятор доступен отдельной кнопкой «Демо». Для
GS1/GS1Sb уже используются официальный построитель команд,
официальный парсер, независимая проверка пакета, оригинальный stateful-алгоритм,
атомарное хранилище и diagnostic GATT-supervisor. Координатор этих частей уже
включён в закрытый диагностический Bluetooth-поток, но реальные JNI-вызовы и
варианты протокола не подтверждены на ARM-устройстве и физическом датчике. До
этого модуль не может подавать данные в реальные тревоги.

Внутренняя граница подключения уже усилена: используется полный activation
profile с точным MAC и кодом, checkpoint физически связан с MAC, generation gate
отвергает поздние callback, а append-only ingress сохраняет notification до
декодирования. Command arbiter закрывает гонку раннего ACK, phase deadlines не
дают callback зависнуть навсегда, reconnect ограничен backoff. Diagnostic runtime
не содержит product stream. Pending-ingress восстанавливается до нового GATT,
терминальный context не обрабатывает хвост, первая причина сбоя неизменяема, а
история не выглядит свежим diagnostic stream. Старый общий GATT-драйвер удалён;
GS3 не проходит через GS1/GS1Sb supervisor.

Глубокий аудит официального APK подтвердил старт настройки через DataMatrix или
восьмисимвольный код. Текущий точный MAC-профиль безопасен для runtime, но пока
нет полного продуктового resolver `код → BLE identity → MAC`; подключаться к
первому похожему устройству запрещено.

Его нельзя постепенно объявить production-кодом только потому, что локальные
контрактные тесты проходят. Следующие барьеры — реальный ARM-smoke, точное
replay-совпадение и полный жизненный цикл отдельного датчика. GS3 проверяется
отдельным трактом.

Продукт принимает только код конкретного сенсора: ровно восемь ASCII-букв или
цифр с сохранением регистра. Обычный декодер чувствительности вызывается первым,
второй официальный декодер — только после точного результата `-1.0`. Это не
подстановка другого идентификатора. Пока продукт допускает только результат
`NORMAL` и обычную инициализацию алгоритма в режиме `0`.

## Не требуется сейчас

- драйверы остальных производителей до завершения GS1/GS1Sb/GS3;
- часы, звонки и SMS;
- микросервисы, Kubernetes и публичная инфраструктура;
- демонстрационные файлы веб-шаблона, которые не участвуют в продукте.

Ничего из этой группы пока не удаляется. Очистка или архивирование выполняются
только после отдельного согласования с владельцем.

## Контроль версий

У продукта пока нет собственной подтверждённой Git-истории: общий репозиторий
не имеет первого коммита, а внутри веб-каталога осталась отдельная история
шаблона. Для безопасных итераций рекомендуется сделать `glucose-monitor`
отдельным репозиторием и только после согласования решить, сохранять или
архивировать вложенную историю веба.
